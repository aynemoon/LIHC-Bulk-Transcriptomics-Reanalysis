# Contributing

Open an issue describing the scientific or reproducibility problem, then submit a focused pull request. Link the relevant dataset, script, expected behavior and validation evidence.

Preserve original attribution. Keep historical source files and reports traceable through the migration manifest. Explain any changes to sample inclusion, normalization, thresholds, annotations or statistical tests. Label newly generated results separately from historical results.

For executable changes, report R and package versions, dataset access dates, sample counts, random seeds where applicable, and validation performed. Do not commit raw datasets, personal local files or unreviewed generated outputs. Discuss licensing with the project owner before introducing a license.

Priority improvements: portable working paths, a documented R/Bioconductor environment, verified sample labels, explicit pipeline inputs and outputs, and an independently checked reproduction.
